# Group Sold Products By The Date

## Инсайт

Для каждой даты нужно получить две характеристики одного и того же множества товаров:

1. количество уникальных товаров;
2. строку из уникальных названий, разделённых запятыми.

Строки сначала группируются по `sell_date`, а повторы товаров устраняются независимо внутри `COUNT` и `STRING_AGG` с помощью `DISTINCT`.

## Текущее решение

### GROUP BY + агрегаты с DISTINCT

```sql
SELECT
    sell_date,
    COUNT(DISTINCT product) AS num_sold,
    STRING_AGG(DISTINCT product, ',') AS products
FROM Activities
GROUP BY sell_date
ORDER BY sell_date;
```

`GROUP BY sell_date` создаёт одну строку результата для каждой даты. `COUNT(DISTINCT product)` считает уникальные товары, а `STRING_AGG(DISTINCT product, ',')` объединяет их названия без повторений.

## Что сделано правильно

- Группировка соответствует требуемому уровню результата: одна строка на дату.
- `COUNT` использует `DISTINCT`, поэтому повторная продажа одного товара в тот же день не увеличивает `num_sold`.
- `STRING_AGG` также использует `DISTINCT`, поэтому название товара не повторяется в итоговой строке.
- Разделитель задан как запятая без пробела, что соответствует формату ответа.
- Внешний `ORDER BY sell_date` правильно сортирует итоговые строки по датам.

## Замечание к решению

Внутри `STRING_AGG` не задан порядок товаров. Без явной сортировки PostgreSQL может передать значения агрегату в произвольном порядке, поэтому результат вроде `Mouse,Keyboard` не гарантированно станет требуемым `Keyboard,Mouse`.

По условию названия внутри `products` должны быть расположены лексикографически. Для этого сортировку по `product` нужно указать непосредственно внутри вызова `STRING_AGG`.

Финальный `ORDER BY sell_date` эту проблему не решает: он сортирует готовые строки по датам, но не элементы внутри уже сформированной строки `products`.

## Два разных порядка

В задаче требуются две независимые сортировки:

| Где выполняется сортировка | Что она упорядочивает |
|---|---|
| внутри `STRING_AGG` | названия товаров одной даты |
| в конце запроса | строки результата по `sell_date` |

Наличие одной сортировки не заменяет другую, потому что они применяются на разных этапах обработки запроса.

## Почему DISTINCT нужен в обоих агрегатах

Если товар был продан несколько раз в один день, он должен учитываться один раз как в количестве, так и в строке названий.

`DISTINCT` внутри `COUNT` не влияет на входные значения `STRING_AGG`, и наоборот. Каждый агрегат обрабатывает свой набор аргументов независимо, поэтому устранение повторов нужно указать в обоих выражениях.

## Что важно запомнить

- **GROUP BY задаёт одну строку на дату.** Все продажи одного дня попадают в одну группу.
- **COUNT DISTINCT считает уникальные товары.** Повторные продажи не увеличивают результат.
- **STRING_AGG объединяет строки через заданный разделитель.** `DISTINCT` удаляет повторяющиеся названия.
- **Порядок внутри агрегата нужно задавать отдельно.** Без него последовательность названий не гарантируется.
- **Внешний ORDER BY не сортирует содержимое STRING_AGG.** Он действует только на готовые строки результата.
- **Оба агрегата требуют собственного DISTINCT.** Настройки одного агрегата не распространяются на другой.
