# Average Time of Process per Machine

## Инсайт

Начало и конец каждого процесса хранятся в разных строках одной таблицы. Чтобы вычислить длительность, нужно сопоставить событие `start` с событием `end` того же процесса на той же машине. После этого длительности суммируются по машине и делятся на количество её процессов.

## Решение

### Self-join + агрегация

```sql
SELECT a1.machine_id, ROUND((SUM(a2.timestamp - a1.timestamp) / COUNT(a1.process_id))::numeric, 3) AS processing_time
FROM Activity a1
JOIN Activity a2 ON (a1.machine_id = a2.machine_id) AND (a1.process_id = a2.process_id) AND (a1.activity_type = 'start') AND (a2.activity_type = 'end')
GROUP BY a1.machine_id;
```

`a1` представляет начало процесса, а `a2` — его конец. Соединение по `machine_id` и `process_id` формирует пары событий, разность временных меток даёт длительность процесса. Затем запрос вычисляет среднюю длительность для каждой машины и округляет её до трёх знаков после запятой.

## Почему соединение выполняется по двум ключам

- `machine_id` гарантирует, что события относятся к одной машине;
- `process_id` гарантирует, что начало сопоставляется с концом того же процесса.

Если использовать только один из этих ключей, события разных процессов или машин могут образовать лишние пары и исказить результат.

## Альтернатива

После формирования пар среднее можно выразить через `AVG` от разности временных меток. Также задачу можно решить условной агрегацией: сначала собрать начало и конец в одну строку для каждого процесса, а затем вычислить среднее по машинам. Текущий self-join хорошо отражает идею прямого сопоставления двух событий.

## Что важно запомнить

- **Self-join связывает разные строки одной таблицы.** Здесь он превращает два события процесса в одну пару `start`/`end`.
- **Фильтры типов событий являются частью условия соединения.** Левая строка должна быть началом, а правая — концом процесса.
- **Среднее можно получить как сумму, делённую на количество.** В данном запросе `COUNT(a1.process_id)` считает сформированные пары процессов.
- **Решение опирается на ограничения задачи.** Для каждого процесса гарантированы ровно одно событие `start` и одно событие `end`; иначе self-join мог бы создать лишние комбинации.
- **Приведение к `numeric` связано с PostgreSQL.** Оно позволяет использовать вариант `ROUND` с указанием количества знаков после запятой.
- **Группировка выполняется по машине.** В результате каждая машина представлена одной строкой со своей средней длительностью.
