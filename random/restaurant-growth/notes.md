# Restaurant Growth

## Инсайт

В исходной таблице за один день может быть несколько посещений, но окно задачи задано в днях. Поэтому сначала нужно получить одну строку на дату с общей дневной выручкой, а уже затем вычислять показатели за текущий и шесть предыдущих дней.

После предварительной агрегации одна строка соответствует одному дню. Благодаря условию задачи о ежедневных посещениях окно из семи строк совпадает с периодом из семи последовательных дней.

## Решение

### Дневная агрегация + оконные функции

```sql
SELECT visited_on, amount, ROUND(average_amount, 2) AS average_amount
FROM (
    SELECT visited_on,
        AVG(amount)
        OVER(
            ORDER BY visited_on
            ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
        ) AS average_amount,
        SUM(amount)
        OVER(
            ORDER BY visited_on
            ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
        ) AS amount,
        COUNT(*)
        OVER(
            ORDER BY visited_on
            ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
        ) AS window_size
    FROM
        (SELECT visited_on, SUM(amount) AS amount
        FROM Customer
        GROUP BY visited_on)
)
WHERE window_size = 7
ORDER BY visited_on;
```

Внутренний подзапрос суммирует платежи за каждый день. Следующий уровень вычисляет скользящую сумму, среднее дневной выручки и фактический размер окна. Внешний запрос оставляет только полные семидневные окна и округляет среднее до двух знаков.

## Почему сначала нужна агрегация по дате

Оконная рамка `ROWS BETWEEN 6 PRECEDING AND CURRENT ROW` отсчитывает строки, а не календарные дни. Если применить её прямо к `Customer`, несколько посетителей одного дня займут несколько позиций окна, и результат перестанет соответствовать семидневному периоду.

После `GROUP BY visited_on` каждая дата представлена ровно одной строкой, поэтому шесть предыдущих строк и текущая строка образуют семь дней.

## Как формируется полное окно

Для первых шести дат PostgreSQL строит неполные окна: предыдущих строк ещё недостаточно. `COUNT(*)` с той же оконной рамкой показывает количество вошедших дней:

| Позиция даты | Размер окна | Попадает в результат |
|---|---:|---|
| 1 | 1 | нет |
| 2 | 2 | нет |
| ... | ... | нет |
| 7 | 7 | да |
| 8 и далее | 7 | да |

Условие `window_size = 7` удаляет первые шесть результатов и оставляет только периоды, для которых доступны все семь дней.

## SUM и AVG считают разные показатели

- `SUM(amount)` по окну возвращает общую выручку за семь дней.
- `AVG(amount)` возвращает среднюю дневную выручку за этот же период.
- `ROUND(average_amount, 2)` приводит среднее к требуемому числу знаков после запятой.

Среднее считается по уже агрегированным дневным суммам, а не по отдельным платежам клиентов.

## Два назначения ORDER BY

- `ORDER BY visited_on` внутри `OVER` задаёт последовательность дней для оконных вычислений.
- Финальный `ORDER BY visited_on` сортирует строки готового результата по возрастанию даты.

Сортировка окна сама по себе не гарантирует порядок выдачи, поэтому обе конструкции выполняют отдельную роль. Внешняя сортировка делает результат полностью соответствующим условию задачи.

## Что важно запомнить

- **Зерно данных должно соответствовать окну.** Перед расчётом семи дней исходные посещения сворачиваются до одной строки на дату.
- **ROWS считает строки.** Семидневным это окно становится только после дневной агрегации и с учётом непрерывности дат из условия задачи.
- **Все оконные показатели используют одну рамку.** `SUM`, `AVG` и `COUNT` относятся к одному и тому же периоду.
- **COUNT помогает отличить полное окно от неполного.** Первые шесть дат не должны попадать в ответ.
- **Оконные функции вычисляются до внешней фильтрации.** Поэтому условие по `window_size` размещено на следующем уровне запроса.
- **Сортировка окна и сортировка результата имеют разные назначения.** Для гарантированного порядка ответа нужен отдельный внешний `ORDER BY`.
