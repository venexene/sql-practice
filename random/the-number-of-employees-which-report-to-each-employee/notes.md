# The Number of Employees Which Report to Each Employee

## Инсайт

Руководители и подчинённые находятся в одной таблице: поле `reports_to` сотрудника указывает на `employee_id` его руководителя. Нужно соединить таблицу саму с собой и для каждого руководителя посчитать непосредственных подчинённых и их средний возраст.

## Решение

### Self-join + GROUP BY + AVG

```sql
SELECT e1.employee_id, e1.name, COUNT(*) AS reports_count, AVG(e2.age)::int AS average_age
FROM Employees e1
JOIN Employees e2 ON e1.employee_id = e2.reports_to
GROUP BY e1.employee_id, e1.name
ORDER BY e1.employee_id;
```

`e1` представляет руководителя, а `e2` - его подчинённого. Каждая строка соединения соответствует одной такой связи. После группировки `COUNT(*)` считает подчинённых, а `AVG(e2.age)` вычисляет их средний возраст. Приведение к `int` округляет среднее до ближайшего целого в PostgreSQL.

## Почему отдельный ROUND не нужен

В PostgreSQL `AVG` целочисленного возраста возвращает `numeric`. Приведение этого типа к `int` выполняет округление до ближайшего целого, а не усечение: среднее 26.4 превращается в 26, а 26.5 и 26.6 - в 27. Поэтому отдельный вызов `ROUND` в текущем варианте избыточен. Это поведение подтверждается [реализацией преобразования numeric в целое в PostgreSQL](https://doxygen.postgresql.org/backend_2utils_2adt_2numeric_8c_source.html#l07789).

Такое поведение не стоит автоматически переносить на другие СУБД или исходные типы данных: правила преобразования могут отличаться.

## Что важно запомнить

- **Направление связи важно.** Идентификатор руководителя сравнивается с `reports_to` подчинённого, а не наоборот.
- **Считаются только непосредственные подчинённые.** Запрос не обходит иерархию и не включает сотрудников нижних уровней.
- **Обычный JOIN соответствует требуемому набору.** В результате нужны только сотрудники, которым кто-то подчиняется. Сохранять остальных через `LEFT JOIN` не требуется.
- **Возраст берётся у подчинённых.** В среднем используется `e2.age`, а не возраст самого руководителя.
- **COUNT(*) считает сотрудников без дополнительного DISTINCT.** Уникальный `employee_id` не позволяет одному подчинённому образовать повторные связи с тем же руководителем в этом соединении.
- **Группировка по идентификатору не объединяет тёзок.** `name` также включён в группу и выводится в результате.
- **AVG прямо выражает вычисление среднего.** Ручное деление суммы на количество сотрудников больше не требуется.
- **В этом запросе ::int также обеспечивает округление.** В PostgreSQL преобразование `numeric` в целое не просто отбрасывает дробную часть.
- **AVG игнорирует NULL.** Если возраст отсутствует, сотрудник учитывается в `reports_count`, но не участвует в вычислении среднего возраста.
- **ORDER BY обязателен по условию.** Руководители выводятся по возрастанию `employee_id`; направление `ASC` подразумевается по умолчанию.
