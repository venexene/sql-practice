# Confirmation Rate

## Инсайт

Для каждого зарегистрированного пользователя нужно разделить количество подтверждённых запросов на общее количество его запросов подтверждения. При этом в результате должны остаться и пользователи, у которых нет ни одной строки в `Confirmations`, — для них доля равна нулю.

## Решение

### LEFT JOIN + агрегатный FILTER

```sql
SELECT s.user_id, ROUND(COUNT(*) FILTER (WHERE c.action = 'confirmed')::numeric/COUNT(*), 2) AS confirmation_rate
FROM Signups s
LEFT JOIN Confirmations c ON s.user_id = c.user_id
GROUP BY s.user_id;
```

`LEFT JOIN` сохраняет всех пользователей из `Signups`. Числитель считает только строки со значением `confirmed`, а знаменатель — все строки пользователя после соединения. Приведение числителя к `numeric` обеспечивает дробное деление, после чего результат округляется до двух знаков.

## Нюанс COUNT(*) после LEFT JOIN

Если у пользователя нет запросов подтверждения, `LEFT JOIN` всё равно создаёт для него одну строку с `NULL` в колонках `Confirmations`. Поэтому знаменатель `COUNT(*)` для такого пользователя равен единице, хотя реальное количество запросов равно нулю.

В этой задаче результат остаётся правильным: отфильтрованный числитель равен нулю, поэтому получается доля `0 / 1 = 0`. Кроме того, такой подход не приводит к делению на ноль. Для пользователей, у которых запросы есть, `COUNT(*)` соответствует их реальному количеству.

## Альтернатива

Долю можно вычислить как среднее числового признака: подтверждённой строке сопоставить единицу, а отклонённой или отсутствующей — ноль. Такой подход напрямую выражает идею «доля подтверждённых событий».

## Что важно запомнить

- **Левой таблицей должна быть `Signups`.** В результате требуется показать каждого зарегистрированного пользователя, даже если у него не было запросов подтверждения.
- **`FILTER` ограничивает строки только для конкретной агрегатной функции.** Группа пользователя сохраняется, но в числитель попадают исключительно подтверждённые действия.
- **Приведение типа выполняется до деления.** Благодаря `::numeric` результат не обрезается до целого числа.
- **`ROUND` применяется к уже вычисленной доле.** По условию результат округляется до двух знаков после запятой.
- **`COUNT(*)` считает строки, созданные внешним соединением.** Это отличается от `COUNT(колонка)`, который игнорирует `NULL`.
- **Решение использует синтаксис PostgreSQL.** Конструкция `FILTER` и сокращённое приведение `::numeric` могут потребовать другой записи в иных СУБД.
