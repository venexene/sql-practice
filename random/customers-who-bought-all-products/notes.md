# Customers Who Bought All Products

## Инсайт

Нужно найти клиентов, которые купили каждый товар из `Product`. Повторная покупка одного товара не увеличивает покрытие каталога, поэтому для каждого клиента считаем разные `product_key` и сравниваем их количество с общим числом товаров.

## Решение

### GROUP BY + COUNT(DISTINCT) + скалярный подзапрос

```sql
SELECT customer_id
FROM Customer
GROUP BY customer_id
HAVING COUNT(DISTINCT product_key) = (SELECT COUNT(*) FROM Product);
```

Группировка собирает покупки каждого клиента. `COUNT(DISTINCT product_key)` определяет количество разных купленных товаров. Подзапрос возвращает размер полного каталога, а `HAVING` оставляет клиентов, у которых эти количества совпадают.

## Почему равенство количеств означает покупку всех товаров

`Product.product_key` является первичным ключом, поэтому каждая строка каталога представляет отдельный товар. `Customer.product_key` является внешним ключом на этот каталог, поэтому клиент не может набрать нужное количество за счёт посторонних товаров.

Набор купленных товаров является подмножеством каталога. Если количество разных купленных товаров равно размеру каталога, ни один товар не пропущен.

Без гарантии принадлежности купленных товаров каталогу одного сравнения количеств было бы недостаточно: два разных набора могут иметь одинаковый размер.

## Альтернатива

Условие можно выразить через проверку отсутствия пропусков: подходит клиент, для которого не существует товара из каталога, который он не купил. Такой подход обычно формулируется через вложенные `NOT EXISTS` и напрямую передаёт смысл «купил все товары».

## Что важно запомнить

- **Повторные покупки не должны увеличивать счётчик.** По условию `Customer` может содержать дубликаты, поэтому обычный `COUNT(*)` здесь не заменяет `COUNT(DISTINCT product_key)`.
- **В каталоге достаточно COUNT(*).** Первичный ключ `product_key` гарантирует уникальность товаров.
- **HAVING проверяет результат агрегации.** Количество купленных товаров вычисляется для группы клиента, а не отдельной строки покупки.
- **Подзапрос возвращает одно общее значение.** Размер каталога одинаков для всех клиентов и не зависит от текущей группы.
- **Ограничения схемы обосновывают решение.** Равенство количеств доказывает полное покрытие только потому, что покупки относятся к товарам каталога.
- **JOIN не требуется для этого подхода.** Для сравнения достаточно размера каталога и количества разных купленных ключей.
- **Сортировка по условию не требуется.** Подходящих клиентов можно вернуть в любом порядке.
