# Find Users With Valid E-Mails

## Инсайт

Адрес нужно проверить целиком, разделив требования на две части:

1. префикс начинается с латинской буквы и затем может содержать буквы, цифры, точку, подчёркивание и дефис;
2. адрес заканчивается точным доменом `@leetcode.com`.

Все условия удобно выразить одним регулярным выражением с якорями начала и конца строки.

## Решение

### Регулярное выражение

```sql
SELECT *
FROM Users
WHERE mail ~ '^[A-Za-z][A-Za-z0-9._-]*@leetcode\.com$';
```

Оператор `~` в PostgreSQL выполняет регистрозависимую проверку по регулярному выражению. Строка попадает в результат, только если весь email соответствует заданному формату.

## Разбор шаблона

```text
^[A-Za-z][A-Za-z0-9._-]*@leetcode\.com$
```

| Часть | Значение |
|---|---|
| `^` | начало строки |
| `[A-Za-z]` | первая позиция префикса обязательно является латинской буквой |
| `[A-Za-z0-9._-]*` | остальные символы префикса из разрешённого набора |
| `@leetcode` | обязательная неизменная часть домена |
| `\.` | обычная точка, а не любой символ |
| `com` | доменная зона |
| `$` | конец строки |

## Почему префикс разделён на две части

Первый класс `[A-Za-z]` требует ровно одну начальную букву. Второй класс содержит более широкий набор допустимых символов и повторяется ноль или больше раз благодаря `*`.

Такой подход допускает префикс из одной буквы, но отклоняет адреса, начинающиеся с цифры, точки, подчёркивания или дефиса.

## Зачем нужны якоря

Без `^` регулярное выражение могло бы найти допустимый фрагмент после неправильных символов в начале строки. Без `$` после домена могли бы находиться дополнительные символы.

Оба якоря вместе означают, что проверяется весь email, а не подходящая подстрока внутри него.

## Почему точка экранирована

В регулярном выражении неэкранированный символ `.` означает любой одиночный символ. Тогда шаблон принял бы, например, `@leetcodeXcom`.

Запись `\.` требует именно обычную точку между `leetcode` и `com`.

## Примеры

| mail | Результат | Причина |
|---|---|---|
| `alice@leetcode.com` | подходит | все условия выполнены |
| `A_1-test@leetcode.com` | подходит | префикс начинается с буквы и содержит разрешённые символы |
| `1alice@leetcode.com` | не подходит | первый символ префикса не является буквой |
| `.alice@leetcode.com` | не подходит | префикс начинается с точки |
| `alice@leetcodeXcom` | не подходит | отсутствует обязательная точка в домене |
| `alice@leetcode.com.org` | не подходит | после требуемого домена есть продолжение |
| `alice@LeetCode.com` | не подходит | домен имеет неправильный регистр |

## Что важно запомнить

- **Первая позиция проверяется отдельно.** Для неё разрешены только латинские буквы.
- **Звёздочка допускает пустой остаток префикса.** Email с префиксом из одной буквы корректен.
- **Дефис расположен в конце класса символов.** В этой позиции он воспринимается буквально, а не задаёт диапазон.
- **Точку в домене нужно экранировать.** Иначе она означает любой символ.
- **Якоря ограничивают всё выражение.** Лишние символы до префикса или после домена не допускаются.
- **Оператор `~` регистрозависим.** Это позволяет проверить домен в точном регистре.
- **Сортировка не требуется.** По условию строки можно вернуть в любом порядке.
