# Movie Rating

## Инсайт

Задача состоит из двух независимых поисков:

1. найти пользователя, который поставил больше всего оценок;
2. найти фильм с наибольшей средней оценкой за февраль 2020 года.

В каждой части после группировки нужно отсортировать группы по вычисленному показателю, разрешить ничью по имени или названию и оставить только первую строку. Затем два результата объединяются через `UNION ALL`.

## Решение

### Два агрегирующих запроса + UNION ALL

```sql
(SELECT u.name AS results
FROM Users u
JOIN MovieRating mr
ON u.user_id = mr.user_id
GROUP BY u.user_id, u.name
ORDER BY COUNT(mr.movie_id) DESC, u.name
LIMIT 1)
UNION ALL
(SELECT m.title
FROM Movies m
JOIN MovieRating mr
ON m.movie_id = mr.movie_id
WHERE '2020-02-01'::date <= mr.created_at AND mr.created_at < '2020-03-01'::date
GROUP BY m.movie_id, m.title
ORDER BY AVG(mr.rating) DESC, m.title
LIMIT 1);
```

Первая часть считает количество оценок каждого пользователя. Сортировка по убыванию `COUNT` ставит самого активного пользователя первым, а `u.name` выбирает лексикографически меньшее имя при равенстве количества оценок.

Вторая часть оставляет оценки за февраль 2020 года и вычисляет среднюю оценку каждого фильма. Сначала фильмы сортируются по убыванию среднего рейтинга, а при равенстве - по названию в лексикографическом порядке.

## Почему нужны два условия сортировки

В обеих частях первое выражение определяет основной критерий победы, а второе обрабатывает ничью:

| Часть | Основной критерий | Разрешение ничьей |
|---|---|---|
| Пользователь | `COUNT(mr.movie_id) DESC` | `u.name` |
| Фильм | `AVG(mr.rating) DESC` | `m.title` |

После такой сортировки `LIMIT 1` оставляет требуемого победителя. Без второго выражения в `ORDER BY` результат при одинаковых показателях не соответствовал бы условию задачи.

## Фильтрация по месяцу

Интервал задан как полуоткрытый:

```sql
'2020-02-01'::date <= mr.created_at
AND mr.created_at < '2020-03-01'::date
```

Левая граница включена, а правая исключена. Такой способ охватывает весь февраль и не требует вручную указывать его последний день. Он также остаётся корректным, если вместо даты колонка содержит время.

## Почему UNION ALL корректен

Каждая часть возвращает ровно одну строку и одну текстовую колонку. Первая часть задаёт ей имя `results`, поэтому это имя получает вся объединённая выборка.

Строки имеют разный смысл и обе должны остаться в ответе, даже если имя пользователя случайно совпадёт с названием фильма. Поэтому нужен именно `UNION ALL`: обычный `UNION` мог бы удалить одну из одинаковых строк.

Скобки вокруг запросов позволяют применить собственные `ORDER BY` и `LIMIT` к каждой части до объединения.

## Почему достаточно JOIN

Обе части ищут победителей только среди существующих оценок, поэтому внутреннее соединение прямо соответствует смыслу задачи.

Пользователь без оценок не может обойти пользователя, который поставил хотя бы одну оценку. Фильм без оценки за февраль также не участвует в вычислении среднего рейтинга. Сохранять такие строки через `LEFT JOIN` не требуется.

## Что важно запомнить

- **Задачу удобно разделить на два независимых запроса.** У частей разные таблицы, агрегаты и правила разрешения ничьей.
- **Правило ничьей является частью сортировки.** После основного показателя нужно указать имя или название по возрастанию.
- **LIMIT применяется после сортировки.** Поэтому остаётся первая строка в уже правильно упорядоченном наборе.
- **JOIN оставляет только строки с оценками.** Пользователи и фильмы без совпадений не участвуют в соответствующих вычислениях.
- **Полуоткрытый диапазон удобен для дат.** Начало следующего месяца служит надёжной верхней границей.
- **UNION ALL сохраняет обе строки.** Это важно, даже если возвращаемые текстовые значения совпадут.
- **Название итоговой колонки задаёт первый SELECT.** Псевдоним `results` распространяется на результат всего объединения.
- **COUNT(mr.movie_id) считает оценки пользователя.** После внутреннего соединения каждой строке результата соответствует существующая оценка.
