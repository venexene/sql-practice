# Employee Bonus

## Инсайт

Нужно вывести сотрудников, чей бонус меньше 1000, а также сотрудников, которым бонус вообще не назначен. Информация о сотрудниках и бонусах хранится в разных таблицах, причём запись в `Bonus` есть не для каждого сотрудника. Поэтому основной таблицей должна быть `Employee`, а бонусы нужно присоединить через `LEFT JOIN`.

## Решение

### LEFT JOIN + явная обработка NULL

```sql
SELECT e.name, b.bonus
FROM Employee e
LEFT JOIN Bonus b ON e.empId = b.empId
WHERE b.bonus < 1000 OR b.bonus IS NULL;
```

`LEFT JOIN` сохраняет всех сотрудников. Если связанная запись в `Bonus` не найдена, значение `b.bonus` становится `NULL`. Условие `WHERE` оставляет бонусы меньше 1000 и отдельно включает сотрудников без бонуса.

## Почему недостаточно сравнения с 1000

В SQL сравнение `NULL` с числом не возвращает `TRUE`. Выражение для проверки бонуса меньше 1000 даст `NULL` для сотрудника без бонуса, и такая строка не пройдёт фильтр. Поэтому отсутствие бонуса нужно проверять отдельно через `IS NULL`.

## Что важно запомнить

- **`LEFT JOIN` сохраняет все строки левой таблицы.** Сотрудник попадёт в промежуточный результат даже без записи в `Bonus`.
- **Порядок таблиц важен.** Слева находится `Employee`, потому что именно сотрудников нельзя потерять.
- **Таблицы соединяются по идентификатору сотрудника.** Условие `e.empId = b.empId` связывает бонус с его владельцем.
- **`NULL` требует отдельной проверки.** Операторы сравнения не включают отсутствующие значения автоматически.
- **Обычный `JOIN` здесь не подходит.** Он исключил бы сотрудников, которым бонус не назначен.
- **Фильтр по правой таблице может изменить смысл `LEFT JOIN`.** Если оставить только условие сравнения бонуса, строки с `NULL` исчезнут из результата.
