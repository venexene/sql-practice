# Delete Duplicate Emails

## Инсайт

Для каждого email нужно сохранить строку с минимальным `id`, а все остальные строки с тем же email удалить.

Задачу удобно разделить на два шага:

1. сгруппировать строки по `email` и найти минимальный `id` каждой группы;
2. удалить строки, идентификаторы которых не входят в набор сохранённых значений.

## Решение

### DELETE + GROUP BY + MIN

```sql
DELETE FROM Person
WHERE id NOT IN (
    SELECT MIN(id) AS id
    FROM Person
    GROUP BY email
);
```

Подзапрос возвращает по одному идентификатору для каждого уникального email. Это строки, которые должны остаться. Внешний `DELETE` удаляет все остальные записи таблицы.

## Как выбирается сохраняемая строка

Для исходных данных:

| id | email |
|---:|---|
| 1 | `a@example.com` |
| 3 | `a@example.com` |
| 5 | `a@example.com` |
| 2 | `b@example.com` |

подзапрос вернёт:

| MIN(id) | email группы |
|---:|---|
| 1 | `a@example.com` |
| 2 | `b@example.com` |

Идентификаторы `3` и `5` не входят в этот набор, поэтому соответствующие строки будут удалены.

## Почему MIN соответствует условию

`GROUP BY email` формирует отдельную группу для каждого адреса, а `MIN(id)` выбирает наименьший идентификатор внутри неё. Количество дубликатов не имеет значения: при двух, трёх или большем числе строк сохраняется ровно одна строка с минимальным `id`.

Уникальный email также образует группу. Её единственный `id` одновременно является минимальным, поэтому такая строка остаётся в таблице.

## Почему NOT IN здесь безопасен

Обычно с `NOT IN` нужно учитывать наличие `NULL` в подзапросе: один `NULL` способен сделать проверку неопределённой для всех строк.

В этой задаче `id` является первичным ключом и не может быть `NULL`. Каждая созданная `GROUP BY` группа содержит хотя бы одну строку, поэтому `MIN(id)` также всегда возвращает ненулевое значение. Следовательно, набор внутри `NOT IN` не содержит `NULL`.

## Это изменение данных

Запрос использует `DELETE`, а не `SELECT`: он изменяет содержимое `Person`. В реальной базе перед массовым удалением полезно сначала проверить тем же условием набор затрагиваемых строк и выполнить операцию в транзакции, если требуется возможность отката.

PostgreSQL позволяет читать целевую таблицу во вложенном подзапросе такого `DELETE`. Подзапрос определяет набор сохраняемых идентификаторов по состоянию таблицы, видимому текущей команде.

## Что важно запомнить

- **GROUP BY определяет группы дубликатов.** Все одинаковые email рассматриваются вместе.
- **MIN выбирает строку, которую нужно сохранить.** Для каждой группы остаётся минимальный `id`.
- **DELETE обрабатывает дополнение к этому набору.** Все идентификаторы вне результата подзапроса удаляются.
- **Уникальные email не затрагиваются.** Их единственные идентификаторы входят в набор `MIN(id)`.
- **NOT IN требует внимания к NULL.** Здесь он корректен благодаря свойствам первичного ключа `id`.
- **Количество повторений не влияет на подход.** Для каждой группы сохраняется ровно одна строка.
- **DML-запросы изменяют данные.** В прикладном коде такие операции стоит проверять и при необходимости выполнять внутри транзакции.
