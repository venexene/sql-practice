# Employees Whose Manager Left the Company

## Инсайт

Нужно найти сотрудников с зарплатой меньше 30000, у которых указан руководитель, но записи этого руководителя больше нет в таблице `Employees`. Для каждого сотрудника можно проверить, существует ли строка с `employee_id`, равным его `manager_id`.

## Решение

### Коррелированный NOT EXISTS

```sql
SELECT e.employee_id
FROM Employees e
WHERE salary < 30000
AND e.manager_id IS NOT NULL
AND NOT EXISTS (
    SELECT 1
    FROM Employees m
    WHERE m.employee_id = e.manager_id)
ORDER BY e.employee_id;
```

Первое условие оставляет сотрудников с подходящей зарплатой, второе исключает тех, кому руководитель не назначен. Коррелированный подзапрос ищет действующего сотрудника с идентификатором, равным `manager_id` текущей строки. `NOT EXISTS` оставляет только случаи, где совпадение не найдено.

## Почему сотрудники без руководителя не попадают в результат

У сотрудника, которому руководитель не назначен, `manager_id` равен `NULL`. Для такого значения условие внутри подзапроса не находит совпадение, поэтому `NOT EXISTS` само по себе вернуло бы `TRUE`.

Явная проверка `e.manager_id IS NOT NULL` исключает эти строки. Отсутствие назначенного руководителя не означает, что руководитель покинул компанию.

## Замечание о NOT IN

Предыдущий вариант можно было выразить через `manager_id NOT IN (SELECT employee_id FROM Employees)`. В этой задаче он корректен, потому что подзапрос выбирает первичный ключ `employee_id`, который не содержит `NULL`.

В общем случае `NOT IN` опасен: если подзапрос возвращает хотя бы один `NULL`, выражение может не вернуть ожидаемые строки из-за трёхзначной логики SQL. `NOT EXISTS` проверяет наличие связанной строки напрямую и не зависит от `NULL` внутри набора подзапроса, но отсутствие значения во внешнем `manager_id` всё равно нужно обработать отдельно.

## Почему подзапрос называется коррелированным

Внутренний запрос обращается к `e.manager_id` из текущей строки внешнего запроса. Его проверка логически повторяется для каждого рассматриваемого сотрудника: «существует ли сейчас менеджер с таким идентификатором?».

`SELECT 1` подчёркивает, что значения из найденной строки не нужны. `EXISTS` проверяет только сам факт её наличия.

## Что важно запомнить

- **Граница зарплаты строгая.** Сотрудник с зарплатой ровно 30000 не подходит, поэтому используется `<`, а не `<=`.
- **Таблица играет две роли.** `e` представляет проверяемого сотрудника, а `m` - возможного действующего руководителя.
- **Проверяется manager_id, а выводится employee_id.** Ответ должен содержать подчинённого, чей руководитель ушёл.
- **NULL означает отсутствие назначенного руководителя.** Такая строка не должна считаться случаем ухода руководителя.
- **IS NOT NULL и NOT EXISTS решают разные задачи.** Первое подтверждает, что руководитель был назначен, второе проверяет отсутствие его записи в компании.
- **EXISTS не требует DISTINCT или COUNT.** Проверка прекращает интересоваться результатом сразу после обнаружения подходящей строки.
- **Коррелированный подзапрос связывается с внешней строкой.** Условие использует `e.manager_id`, поэтому проверка относится к конкретному сотруднику.
- **Замечание о NOT IN остаётся важным.** Его поведение зависит от возможности появления `NULL` в подзапросе.
- **ORDER BY задан явно.** Без него порядок строк результата не гарантируется, а условие требует сортировку по `employee_id`.
