# Game Play Analysis IV

## Инсайт

Нужно найти долю игроков, которые вернулись на следующий календарный день после своего первого входа. Важно проверять следующий день именно относительно первой даты активности, а не искать произвольные два последовательных дня игры.

## Решение

### MIN в подзапросе + JOIN + FILTER

```sql
SELECT ROUND(COUNT(*) FILTER(WHERE a.event_date = ma.min_date + INTERVAL '1 day')::numeric / COUNT(DISTINCT a.player_id), 2) AS fraction
FROM
    (SELECT player_id, MIN(event_date) AS min_date
    FROM Activity
    GROUP BY player_id) AS ma
JOIN Activity a ON a.player_id = ma.player_id;
```

Подзапрос находит первую дату активности каждого игрока. Соединение добавляет эту дату ко всем записям его активности. Числитель считает записи, дата которых ровно на один день позже первой даты, а знаменатель — всех уникальных игроков.

Приведение числителя к `numeric` обеспечивает дробное деление. Итоговая доля округляется до двух знаков после запятой и выводится в колонке `fraction`.

## Почему способы подсчёта различаются

После соединения один игрок может быть представлен несколькими строками — по одной на каждую дату активности. Поэтому обычный `COUNT(*)` в знаменателе посчитал бы дни активности, а не игроков. Нужен `COUNT(DISTINCT a.player_id)`.

В числителе `COUNT(*)` корректен: по условию пара `player_id` и `event_date` является первичным ключом. Для одного игрока существует не больше одной записи на следующий день после первого входа, поэтому количество подходящих строк совпадает с количеством вернувшихся игроков.

## Альтернатива

Можно начать с набора первых дат и через `LEFT JOIN` присоединять только активность на следующий день. Тогда каждый игрок останется в наборе, даже если не вернулся, а долю можно вычислить по наличию совпадения. Обычный `JOIN` с таким условием не подошёл бы: он исключил бы невернувшихся игроков из знаменателя.

## Что важно запомнить

- **Точка отсчёта — первый вход.** `MIN(event_date)` вычисляется отдельно для каждого игрока.
- **Следующий день — календарный, а не следующая строка.** Следующая запись активности может быть через несколько дней и не соответствовать условию.
- **INTERVAL выражает сдвиг даты.** Прибавление одного дня позволяет проверить точное совпадение с нужной датой в PostgreSQL.
- **Знаменатель должен учитывать всех игроков.** Нельзя исключать тех, кто не вернулся на следующий день.
- **FILTER ограничивает только числитель.** Остальные записи остаются доступны для подсчёта общего количества игроков.
- **Уникальность ключа влияет на выбор COUNT.** Уникальная пара «игрок — дата» позволяет считать подходящие строки без дополнительного `DISTINCT` в числителе.
- **Доля — не процент.** По условию требуется число от 0 до 1, поэтому умножать на 100 не нужно.
- **Приведение типа выполняется до деления.** Иначе целочисленные счётчики могут потерять дробную часть.
- **Округляется итоговая доля.** `ROUND` применяется после деления.
