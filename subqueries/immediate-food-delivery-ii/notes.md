# Immediate Food Delivery II

## Инсайт

Процент нужно считать не среди всех заказов, а только среди первых заказов каждого клиента. Заказ считается немедленным, если дата заказа совпадает с желаемой датой доставки. Поэтому сначала нужно найти минимальную дату заказа для каждого клиента, а затем проверить соответствующий заказ.

## Решение

### Подзапрос с MIN + JOIN + FILTER

```sql
SELECT
    ROUND(COUNT(*) FILTER(WHERE(order_date = customer_pref_delivery_date))::numeric / COUNT(*) * 100, 2) AS immediate_percentage
FROM
    (SELECT customer_id, MIN(d1.order_date) AS first_order_date
    FROM Delivery d1
    GROUP BY customer_id) as fd
JOIN Delivery d ON fd.customer_id = d.customer_id AND d.order_date = fd.first_order_date;
```

Подзапрос возвращает одну минимальную дату для каждого клиента. Соединение с `Delivery` выполняется по клиенту и этой дате, поэтому в итоговом наборе остаются только первые заказы.

Обычный `COUNT(*)` в знаменателе считает все первые заказы. `FILTER` в числителе оставляет среди них только немедленные — с совпадающими датами заказа и желаемой доставки. Приведение числителя к `numeric` обеспечивает дробное деление; затем доля умножается на 100 и округляется до двух знаков.

## Что важно запомнить

- **Правильно выбрать набор для расчёта процента.** Знаменатель должен содержать первые заказы, а не все доставки.
- **Первый заказ определяется датой, а не идентификатором.** `MIN(order_date)` соответствует определению из условия.
- **Минимальная дата ищется отдельно для каждого клиента.** Для этого подзапрос группируется по `customer_id`.
- **По условию первый заказ каждого клиента уникален.** Поэтому совпадение с минимальной датой выбирает ровно один заказ клиента.
- **Немедленность проверяется равенством дат.** Условие сравнивает `order_date` и `customer_pref_delivery_date`.
- **JOIN отбирает первые заказы, а FILTER проверяет немедленность.** Поздние немедленные заказы не попадают в набор и не влияют на процент.
- **Приведение к numeric выполняется до деления.** Иначе целочисленные счётчики могут дать обрезанную долю в PostgreSQL.
- **Округляется итоговый процент.** Сначала вычисляется доля и умножается на 100, затем применяется `ROUND`.
