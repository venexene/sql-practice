# Percentage of Users Attended a Contest

## Инсайт

Для каждого конкурса нужно разделить количество зарегистрированных на него пользователей на общее количество пользователей из `Users`, а затем умножить результат на 100. Числитель меняется от конкурса к конкурсу, а знаменатель одинаков для всех групп.

## Решение

### GROUP BY + скалярный подзапрос

```sql
SELECT contest_id, ROUND(COUNT(user_id)::numeric/(SELECT COUNT(user_id) FROM Users)*100, 2) AS percentage
FROM Register
GROUP BY contest_id
ORDER BY percentage DESC, contest_id ASC;
```

Группировка собирает регистрации по конкурсам. `COUNT(user_id)` вычисляет количество участников каждого конкурса, а подзапрос возвращает общее число пользователей. После дробного деления доля переводится в проценты и округляется до двух знаков после запятой.

## Почему знаменатель берётся из Users

Один пользователь может зарегистрироваться на несколько конкурсов. Поэтому общее количество строк в `Register` — это число регистраций, а не число пользователей. По условию процент рассчитывается относительно всех пользователей, включая тех, кто не зарегистрировался ни на один конкурс.

## Что важно запомнить

- **GROUP BY задаёт уровень подсчёта.** Для каждого `contest_id` формируется отдельная группа регистраций.
- **DISTINCT здесь не требуется.** Пара `contest_id` и `user_id` является первичным ключом, поэтому пользователь не встречается в одном конкурсе повторно.
- **Подзапрос возвращает одно значение.** Агрегатный `COUNT` без группировки даёт одну строку, которую можно использовать как знаменатель в выражении.
- **Подзапрос не зависит от текущего конкурса.** Он считает пользователей всей таблицы `Users`, а не участников отдельной группы.
- **JOIN не нужен для получения общего количества.** Здесь достаточно скалярного подзапроса; соединение со всеми пользователями могло бы лишний раз размножить строки.
- **Приведение к numeric выполняется до деления.** Это предотвращает целочисленное деление в PostgreSQL. Умножение на 100 после уже обрезанного результата дробную часть не восстановило бы.
- **ROUND применяется после перевода доли в проценты.** Округлять нужно итоговое значение, а не промежуточную долю.
- **Сортировка может иметь несколько критериев.** Сначала используется `percentage DESC`, а при равных процентах — `contest_id ASC`.
- **Псевдоним выходной колонки можно использовать в ORDER BY.** Это позволяет не повторять выражение вычисления процента.
