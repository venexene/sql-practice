# User Activity for the Past 30 Days I

## Инсайт

Нужно посчитать уникальных активных пользователей за каждый день 30-дневного периода, заканчивающегося 27 июля 2019 года включительно. Один пользователь может совершать несколько действий и участвовать в нескольких сессиях за день, но должен учитываться только один раз.

## Решение

### Фильтрация по датам + GROUP BY + COUNT(DISTINCT)

```sql
SELECT activity_date AS day, COUNT(DISTINCT user_id) AS active_users
FROM Activity
WHERE '2019-07-27'::date - INTERVAL '30 days' < activity_date AND activity_date <= '2019-07-27'::date
GROUP BY activity_date;
```

`WHERE` оставляет активность нужного периода. Затем строки группируются по дате, а `COUNT(DISTINCT user_id)` считает разных пользователей внутри каждого дня. Псевдонимы `day` и `active_users` задают требуемые имена колонок результата.

## Почему нижняя граница строгая

Вычитание 30 дней из 27 июля даёт 27 июня. Эта дата исключается условием `< activity_date`, а конечная дата включается через `<=`. Поэтому фактический диапазон - с 28 июня по 27 июля включительно, ровно 30 дней.

Если включить обе границы при вычитании 30 дней, получится 31 день. Альтернативный способ задать тот же период - вычесть 29 дней и включить обе границы.

## Что важно запомнить

- **Границы периода нужно проверять вместе.** Количество календарных дней зависит не только от интервала, но и от строгости сравнений.
- **COUNT(DISTINCT) считает пользователей, а не события.** Несколько действий одного пользователя в один день не увеличивают результат.
- **Уникальность проверяется отдельно для каждого дня.** Один пользователь может учитываться в нескольких датах периода.
- **Любая запись активности делает пользователя активным в этот день.** Дополнительный фильтр по типу действия не требуется.
- **Фильтрация выполняется до группировки.** Сначала выбирается период, затем вычисляются дневные показатели.
- **Дни без активности не выводятся.** GROUP BY формирует группы только для дат, представленных в отфильтрованных строках; это соответствует условию задачи.
- **Дата окончания фиксирована условием.** Использовать текущую дату вместо 27 июля 2019 года не нужно.
- **Приведение через ::date и INTERVAL подходят для PostgreSQL.** В другой СУБД синтаксис арифметики дат может отличаться.
- **Сортировка по условию не требуется.** Строки результата можно вернуть в любом порядке.
