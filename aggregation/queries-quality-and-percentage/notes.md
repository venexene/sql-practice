# Queries Quality and Percentage

## Инсайт

Для каждой группы с одинаковым `query_name` нужно вычислить две независимые метрики:

- `quality` — среднее отношение `rating / position` по строкам группы;
- `poor_query_percentage` — процент строк, в которых `rating < 3`.

Все строки участвуют в расчёте качества и общего количества запросов. Условие низкого рейтинга ограничивает только числитель второй метрики.

## Решение

### GROUP BY + AVG + FILTER

```sql
SELECT
    query_name,
    ROUND(AVG(rating::numeric/position), 2) AS quality,
    ROUND(COUNT(*) FILTER (WHERE rating < 3)::numeric/COUNT(*)*100, 2) AS poor_query_percentage
FROM Queries
GROUP BY query_name;
```

Для качества сначала вычисляется дробное отношение рейтинга к позиции каждой строки, затем `AVG` находит среднее этих отношений по группе. Для процента плохих запросов отфильтрованный `COUNT` делится на общее количество строк и умножается на 100. Обе итоговые метрики округляются до двух знаков после запятой.

## Среднее отношений — не отношение сумм

Если строки имеют рейтинг и позицию `(5, 1)` и `(1, 2)`, качество равно `(5 / 1 + 1 / 2) / 2 = 2.75`. Деление суммы рейтингов на сумму позиций дало бы `(5 + 1) / (1 + 2) = 2`, что не соответствует определению метрики.

## Что важно запомнить

- **Приведение типа должно предшествовать делению.** `rating::numeric` сохраняет дробную часть каждого отношения, а приведение отфильтрованного `COUNT` обеспечивает дробный процент.
- **FILTER применяется только к своему агрегату.** Другие агрегаты продолжают учитывать все строки группы.
- **WHERE с условием низкого рейтинга здесь не подходит.** Он исключил бы остальные строки до группировки, изменив качество и знаменатель процента.
- **Граница плохого рейтинга строгая.** Рейтинг 3 не считается плохим: условие требует `rating < 3`.
- **COUNT(*) учитывает все записи, включая дубликаты.** По условию таблица может содержать повторяющиеся строки; удалять их перед расчётом не нужно.
- **Округляются итоговые метрики.** Промежуточные отношения округлять не следует, чтобы не искажать среднее.
- **Делитель положителен в каждой сформированной группе.** `COUNT(*)` не равен нулю, а `position` по условию принимает значения от 1 до 500, поэтому защита от деления на ноль здесь не требуется.
- **Сортировка по условию не требуется.** Результат можно вернуть в любом порядке.
- **FILTER и приведение через :: используются в PostgreSQL.** Для другой СУБД синтаксис может потребовать адаптации.
