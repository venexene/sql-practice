# Count Salary Categories

## Инсайт

Нужно распределить счета по трём категориям дохода и посчитать их количество. При этом каждая категория должна присутствовать в результате, даже если в ней нет счетов.

Одна группировка классифицированных счетов не создаст строки для пустых категорий. Поэтому сначала задаётся полный список категорий через `VALUES`, а затем к нему присоединяются счета через `LEFT JOIN`.

## Решение

### VALUES + CASE + LEFT JOIN + COUNT

```sql
SELECT c.category, COUNT(account_id) AS accounts_count
FROM (
    VALUES
        ('Low Salary'),
        ('Average Salary'),
        ('High Salary')
) AS c(category)
LEFT JOIN (
    SELECT *, CASE
                WHEN income < 20000 THEN 'Low Salary'
                WHEN income > 50000 THEN 'High Salary'
                ELSE 'Average Salary'
              END AS category
    FROM Accounts
) AS a
ON c.category = a.category
GROUP BY c.category;
```

`VALUES` создаёт таблицу с тремя категориями. Подзапрос `a` добавляет каждому счёту категорию через `CASE`. Внешнее соединение сохраняет полный список категорий, а группировка и `COUNT(account_id)` вычисляют количество соответствующих счетов.

## Границы категорий

- `Low Salary`: доход строго меньше 20000.
- `Average Salary`: доход от 20000 до 50000 включительно.
- `High Salary`: доход строго больше 50000.

Строгие условия первых двух ветвей оставляют значения 20000 и 50000 для `ELSE`, поэтому обе границы относятся к средней категории.

## Почему COUNT(account_id), а не COUNT(*)

Для пустой категории `LEFT JOIN` создаёт одну строку с `NULL` в колонках счетов. `COUNT(*)` посчитал бы её и ошибочно вернул 1. `COUNT(account_id)` игнорирует `NULL`, поэтому возвращает требуемый 0.

Для найденных счетов `account_id` не равен `NULL`, поскольку является первичным ключом, поэтому каждый счёт учитывается.

## Что важно запомнить

- **Полный список категорий задаётся отдельно от данных.** Это позволяет выводить категории, отсутствующие в исходных счетах.
- **VALUES можно использовать как источник строк.** Запись `AS c(category)` задаёт псевдоним таблицы и имя её колонки.
- **CASE классифицирует, не удаляя строки.** Каждый счёт получает категорию, после чего используется в подсчёте.
- **Левой стороной соединения должен быть список категорий.** Именно эти строки требуется сохранить все.
- **COUNT(колонка) игнорирует NULL.** Это обеспечивает ноль для отсутствующих совпадений после внешнего соединения.
- **Подсчёт выполняется по account_id.** Счета с одинаковым доходом остаются отдельными счетами; удалять их через `DISTINCT income` нельзя.
- **Обычного GROUP BY по счетам недостаточно.** Он выводит только категории, для которых существуют исходные строки.
- **Сортировка по условию не требуется.** Порядок категорий в `VALUES` сам по себе не гарантирует порядок итогового результата.
