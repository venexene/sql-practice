# Investments in 2016

## Инсайт

В итоговую сумму входят только страхователи, для которых одновременно выполняются два условия:

1. значение `tiv_2015` встречается более одного раза;
2. пара координат `(lat, lon)` встречается ровно один раз.

Оба условия зависят от количества строк внутри своей группы. Их удобно вычислить оконными `COUNT`, поскольку оконные функции сохраняют исходные строки и позволяют после подсчёта суммировать соответствующие им значения `tiv_2016`.

## Решение

### Два оконных COUNT + фильтрация

```sql
SELECT ROUND(SUM(tiv_2016)::numeric, 2) AS tiv_2016
FROM (
    SELECT
        tiv_2015,
        tiv_2016,
        COUNT(*) OVER (PARTITION BY lat, lon) AS cnt1,
        COUNT(*) OVER (PARTITION BY tiv_2015) AS cnt2
    FROM Insurance
)
WHERE cnt1 = 1 AND cnt2 != 1;
```

`cnt1` показывает, сколько полисов относится к той же географической точке, а `cnt2` - сколько раз встречается то же значение инвестиции за 2015 год. После фильтрации `SUM` складывает `tiv_2016` оставшихся строк, а `ROUND` округляет результат до двух знаков.

## Что считают оконные функции

### Уникальность координат

```sql
COUNT(*) OVER (PARTITION BY lat, lon)
```

Строки группируются окном сразу по двум координатам. Значение `1` означает, что конкретная пара `(lat, lon)` уникальна. Проверять уникальность `lat` и `lon` по отдельности было бы неверно: условие относится именно к их сочетанию.

### Повторение tiv_2015

```sql
COUNT(*) OVER (PARTITION BY tiv_2015)
```

Если результат больше `1`, существует хотя бы ещё один страхователь с таким же `tiv_2015`. В текущем запросе это выражено как `cnt2 != 1`. Поскольку `COUNT(*)` для исходной строки всегда не меньше единицы, условие работает корректно, но `cnt2 > 1` передавало бы смысл задачи прямее.

## Почему нужен подзапрос

Оконные функции вычисляются после `WHERE` на том же уровне запроса, поэтому обратиться к `cnt1` и `cnt2` непосредственно в фильтре нельзя. Подзапрос сначала рассчитывает оба счётчика для полного набора данных, а внешний запрос уже фильтрует строки по готовым значениям.

Если отфильтровать данные до оконных вычислений, размеры групп изменятся и проверки уникальности перестанут описывать исходную таблицу.

## Почему внешний GROUP BY не нужен

Финальная часть запроса должна сложить `tiv_2016` всех подходящих страхователей в одно значение. Агрегат без `GROUP BY` рассматривает весь отфильтрованный набор как одну группу, что и соответствует условию задачи.

Это также сохраняет правильную форму результата в пограничном случае без подходящих строк:

- запрос всё равно возвращает одну строку;
- значение `SUM` в ней равно `NULL`.

Если сгруппировать по `cnt1`, при пустом наборе не будет создано ни одной группы и запрос не вернёт строку вообще.

Приведение `SUM(tiv_2016)` к `numeric` позволяет использовать двухаргументный вариант `ROUND` в PostgreSQL и явно округлить сумму до двух знаков после запятой.

## Что важно запомнить

- **Условия должны выполняться одновременно.** Строка включается в сумму только при уникальных координатах и повторяющемся `tiv_2015`.
- **Координаты проверяются парой.** Уникальность определяется по `(lat, lon)`, а не по каждой колонке отдельно.
- **Оконные функции сохраняют строки.** В отличие от обычного `GROUP BY`, они добавляют размер группы к каждой исходной записи.
- **Фильтрация выполняется после вычисления окон.** Для этого используется внешний уровень запроса.
- **COUNT всегда не меньше единицы для существующей строки.** Поэтому `cnt2 != 1` эквивалентно `cnt2 > 1`, хотя второй вариант понятнее.
- **Для одной общей суммы GROUP BY не нужен.** Весь отфильтрованный набор должен образовать одну агрегатную группу.
- **ROUND применяется к общей сумме.** Сначала складываются все подходящие `tiv_2016`, затем результат округляется до двух знаков.
