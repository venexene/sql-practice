# Last Person to Fit in the Bus

## Инсайт

Для каждого человека нужно знать общий вес всех людей от начала очереди до него включительно. Это накопительная сумма по порядку `turn`. Среди строк с суммой не больше 1000 нужно выбрать человека с самым большим номером очереди.

## Решение

### Оконный SUM + фильтрация + ORDER BY + LIMIT

```sql
SELECT person_name FROM (
    SELECT *, SUM(weight) OVER(ORDER BY turn) AS sum_weight
    FROM Queue
)
WHERE sum_weight <= 1000
ORDER BY turn DESC
LIMIT 1;
```

Внутренний запрос добавляет к каждому человеку накопительный вес. Внешний фильтр оставляет тех, до кого общий вес не превышает вместимость автобуса. Сортировка по убыванию `turn` ставит последнего подходящего человека первым, а `LIMIT 1` оставляет только его имя.

## Два назначения сортировки

В запросе используются два разных порядка:

- `ORDER BY turn` внутри `OVER` определяет, какие люди входят в накопительную сумму;
- внешняя сортировка по убыванию `turn` определяет, кого выбрать первым через `LIMIT 1`.

Сортировка для выбора ответа находится во внешнем запросе, на том же уровне, что и `LIMIT`. Это явно закрепляет нужный порядок результата, а не полагается на порядок строк подзапроса. См. [документацию PostgreSQL о сортировке результата](https://www.postgresql.org/docs/16/queries-order.html).

## Как работает накопительный вес

| turn | weight | sum_weight | Проходит фильтр |
|---|---|---|---|
| 1 | 400 | 400 | Да |
| 2 | 500 | 900 | Да |
| 3 | 200 | 1100 | Нет |
| 4 | 50 | 1150 | Нет |

Последний подходящий человек имеет `turn = 2`. Человек с номером 4 не может пройти вместо человека с номером 3: посадка идёт по очереди, а не по индивидуальному весу.

## Что важно запомнить

- **Оконный SUM сохраняет отдельные строки.** В отличие от обычной агрегации, он добавляет сумму к каждому человеку, не сворачивая очередь в одну строку.
- **Порядок задаётся turn, а не person_id.** Идентификатор человека не определяет его место в очереди.
- **Текущий человек входит в накопительную сумму.** Нужно проверить вес автобуса после его посадки, а не до неё.
- **Ровно 1000 допустимо.** Поэтому используется `<=`, а не строгое сравнение.
- **Положительные веса делают сумму возрастающей.** После превышения лимита более поздние строки также не проходят фильтр; пропускать людей нельзя.
- **Фильтр по результату окна вынесен наружу.** Сначала вычисляется `sum_weight`, затем внешний `WHERE` использует эту колонку.
- **LIMIT сам не определяет, какая строка первая.** Для выбора последнего человека нужен явно заданный убывающий порядок во внешнем запросе.
- **Turn уникален по условию.** Поэтому стандартная рамка окна при таком порядке даёт нужную накопительную сумму без объединения строк с одинаковой позицией.
- **По условию первый человек помещается.** Подходящий ответ существует, поэтому отдельная обработка пустого результата не нужна.
- **Подзапрос без псевдонима допустим начиная с PostgreSQL 16.** Для более старых версий ему нужно присвоить имя.
