# Consecutive Numbers

## Инсайт

Нужно найти значения, которые встречаются как минимум три раза подряд в порядке `id`. Общее количество повторений не подходит: три одинаковых значения могут быть разделены другими числами.

Для каждой строки достаточно сравнить текущее значение с двумя предыдущими. Если все три совпадают, найдена серия нужной длины. Оконная функция `LAG` позволяет получить значения соседних строк, не объединяя строки в группы.

## Решение

### LAG с двумя смещениями + внешний WHERE + DISTINCT

```sql
SELECT DISTINCT num AS ConsecutiveNums
FROM (
    SELECT
        id,
        num,
        LAG(num, 1) OVER (ORDER BY id) AS prev1,
        LAG(num, 2) OVER (ORDER BY id) AS prev2
    FROM Logs
)
WHERE num = prev1 AND num = prev2;
```

Внутренний запрос сохраняет каждую строку и добавляет к ней два значения: `prev1` из предыдущей строки и `prev2` из строки двумя позициями раньше. Внешний запрос оставляет строки, где текущее число совпадает с обоими соседями. `DISTINCT` возвращает каждое найденное число только один раз.

## Как работает сравнение

Для последовательности `1, 1, 1, 1, 2`:

| id | num | prev1 | prev2 | Проходит фильтр |
|---|---|---|---|---|
| 1 | 1 | NULL | NULL | Нет |
| 2 | 1 | 1 | NULL | Нет |
| 3 | 1 | 1 | 1 | Да |
| 4 | 1 | 1 | 1 | Да |
| 5 | 2 | 1 | 1 | Нет |

Третья и четвёртая строки обе подтверждают наличие серии. После `DISTINCT` в результате остаётся одна строка со значением `1`.

## Почему нужен внешний запрос

Оконные функции вычисляются после `WHERE` того же уровня запроса. Поэтому нельзя сначала вычислить `LAG` в `SELECT` и сразу использовать его результат в `WHERE` этого же запроса.

Подзапрос разделяет этапы: сначала добавляет предыдущие значения к строкам, затем внешний `WHERE` фильтрует уже готовый набор. Эту же структуру можно оформить через CTE.

## Что было сложно

Новая идея здесь - переход от подсчёта групп к сравнению строк в последовательности. `GROUP BY` сворачивает строки, а оконная функция сохраняет их и позволяет обращаться к соседям.

Чтобы восстановить решение без подсказки, полезно проговорить три шага:

1. Задать порядок строк по `id`.
2. Добавить значения из двух предыдущих строк.
3. Проверить совпадение трёх значений и убрать повторные ответы.

## Что важно запомнить

- **OVER (ORDER BY id) задаёт порядок для LAG.** Без определённого порядка понятие предыдущей строки не соответствует задаче.
- **Смещение LAG измеряется строками.** Это предыдущая строка в заданном порядке, а не поиск записи с идентификатором `id - 1`.
- **Первые строки получают NULL для отсутствующих соседей.** Сравнения с ними не дают `TRUE`, поэтому неполные тройки не проходят фильтр.
- **Серии длиннее трёх тоже находятся.** Каждая строка начиная с третьей внутри серии подтверждает подходящую тройку.
- **DISTINCT нужен для итоговых значений.** Одно число может встретиться в длинной серии или в нескольких отдельных сериях.
- **Общая частота не доказывает последовательность.** Подсчёт через `GROUP BY num` потерял бы информацию о расположении чисел.
- **Порядок окна и порядок результата - разные вещи.** `ORDER BY` внутри `OVER` управляет вычислением соседей, но не гарантирует сортировку итоговой таблицы. По условию она не требуется.
- **Подзапрос без псевдонима зависит от версии PostgreSQL.** Его можно не именовать начиная с [PostgreSQL 16](https://www.postgresql.org/docs/16/release-16.html); для более старых версий нужно добавить псевдоним.
