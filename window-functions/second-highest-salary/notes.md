# Second Highest Salary

## Инсайт

Нужно вернуть вторую максимальную уникальную зарплату. В результате всегда должна быть ровно одна строка: если второй уникальной зарплаты нет, её значение должно быть `NULL`.

Текущее решение создаёт строку с искомым рангом `2`, вычисляет плотный ранг зарплат и соединяет эти наборы через `LEFT JOIN`. Строка с рангом `2` служит якорем и сохраняется даже при отсутствии совпадения.

## Решение

### Строка-якорь + DENSE_RANK + LEFT JOIN

```sql
SELECT e.salary AS SecondHighestSalary
FROM (
    VALUES (
        (2)
    )
) AS t(rank)
LEFT JOIN (
    SELECT
        salary,
        DENSE_RANK() OVER(ORDER BY salary DESC) AS rank
    FROM Employee
) AS e
ON t.rank = e.rank
LIMIT 1;
```

Подзапрос `t` содержит одну строку со значением `rank = 2`. Второй подзапрос ранжирует зарплаты от большей к меньшей. `LEFT JOIN` ищет строки со вторым рангом, но сохраняет строку из `t`, даже если совпадения нет.

## Почему нужен DENSE_RANK

Задача относится к уникальным значениям зарплаты, а не к позициям отдельных сотрудников. `DENSE_RANK` присваивает одинаковым зарплатам одинаковый ранг и не оставляет пропусков после ничьей.

Для зарплат `100`, `100`, `90`, `80` функции дали бы разные результаты:

| salary | RANK | DENSE_RANK |
|---:|---:|---:|
| 100 | 1 | 1 |
| 100 | 1 | 1 |
| 90 | 3 | 2 |
| 80 | 4 | 3 |

С `RANK` значение `90` получает ранг `3`, поэтому строки с рангом `2` вообще нет. `DENSE_RANK` правильно определяет `90` как вторую максимальную уникальную зарплату.

## Зачем нужна строка-якорь

Если просто отфильтровать результат оконной функции по второму рангу, при отсутствии второй зарплаты запрос вернёт ноль строк. Но условие требует одну строку со значением `NULL`.

Одиночная строка `t` находится слева от `LEFT JOIN` и поэтому не исчезает. Когда ранг `2` отсутствует, все колонки подзапроса `e`, включая `salary`, получают `NULL`.

## Почему нужен LIMIT 1

Несколько сотрудников могут получать одинаковую вторую зарплату. `DENSE_RANK` присвоит всем таким строкам ранг `2`, и соединение вернёт каждую из них.

Все совпавшие значения `salary` одинаковы, поэтому `LIMIT 1` безопасно оставляет одну строку с нужной зарплатой. Без него форма результата нарушалась бы: вместо одной строки запрос мог вернуть несколько.

## Зафиксированные ошибки

### Использование RANK вместо DENSE_RANK

Первоначально использовался `RANK`. После повторяющейся максимальной зарплаты он оставляет пропуск в нумерации, из-за чего вторая уникальная зарплата может не получить ранг `2`.

Исправление - использовать `DENSE_RANK`, который нумерует уникальные значения последовательно.

### Отсутствие LIMIT

Первоначально в запросе не было `LIMIT 1`. При нескольких сотрудниках с одинаковой второй зарплатой соединение возвращало несколько одинаковых строк.

Исправление - оставить одну из этих строк через `LIMIT 1`, поскольку значение зарплаты у всех совпадений одинаковое.

## Пограничные случаи

- Одна строка в таблице - второго ранга нет, результатом становится `NULL`.
- Все сотрудники имеют одинаковую зарплату - существует только первый ранг, результатом становится `NULL`.
- Несколько сотрудников имеют вторую зарплату - после соединения возникает несколько одинаковых строк, но `LIMIT 1` оставляет одну.
- Максимальная зарплата повторяется - `DENSE_RANK` всё равно присваивает следующей уникальной зарплате ранг `2`.

## Что важно запомнить

- **Ищется второе уникальное значение.** Повторения одной зарплаты не создают новые позиции.
- **DENSE_RANK не оставляет пропусков.** Поэтому он подходит для нумерации уникальных зарплат.
- **RANK может пропустить второй номер.** Это происходит, если максимальная зарплата встречается несколько раз.
- **LEFT JOIN сохраняет строку-якорь.** При отсутствии совпадения получается требуемый `NULL`.
- **LIMIT гарантирует одну строку.** Он удаляет повторы второй зарплаты в итоговой выдаче.
- **Все строки второго ранга имеют одинаковую зарплату.** Поэтому выбор любой одной из них корректен и не требует дополнительной сортировки.
