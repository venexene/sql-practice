# Department Top Three Salaries

## Инсайт

Нужно выбрать не просто трёх сотрудников с наибольшими зарплатами, а сотрудников, чьи зарплаты входят в три максимальных уникальных значения внутри их отдела.

Если несколько сотрудников получают одинаковую зарплату, все они должны занять одно место и попасть в результат вместе. Поэтому задачу удобно решать через `DENSE_RANK`, разделив строки по отделам и упорядочив зарплаты по убыванию.

## Решение

### JOIN + DENSE_RANK

```sql
SELECT Department, Employee, Salary
FROM (
    SELECT
        d.name AS Department,
        e.name AS Employee,
        e.salary AS Salary,
        DENSE_RANK() OVER(
            PARTITION BY e.departmentId
            ORDER BY e.salary DESC
        ) AS rank
    FROM Department d
    JOIN Employee e
    ON d.id = e.departmentId
)
WHERE rank <= 3;
```

`JOIN` добавляет к каждому сотруднику название его отдела. Оконная функция независимо ранжирует зарплаты внутри каждого отдела, а внешний запрос оставляет первые три позиции рейтинга.

## Почему нужен DENSE_RANK

Рассмотрим зарплаты одного отдела:

| Зарплата | DENSE_RANK |
|---:|---:|
| 100000 | 1 |
| 90000 | 2 |
| 90000 | 2 |
| 80000 | 3 |
| 70000 | 4 |

Одинаковые зарплаты получают одинаковый ранг, а следующее уникальное значение получает следующий последовательный номер. Поэтому фильтр `rank <= 3` вернёт обе строки с зарплатой 90000 и строку с зарплатой 80000.

### Почему не ROW_NUMBER

`ROW_NUMBER` присвоил бы каждой строке отдельный номер. Тогда из нескольких сотрудников с одинаковой граничной зарплатой часть могла бы попасть в первые три строки, а часть - нет.

### Почему не RANK

`RANK` также объединяет одинаковые значения, но оставляет пропуски после ничьей. В примере ранги были бы `1, 2, 2, 4, 5`, поэтому третья уникальная зарплата получила бы ранг `4` и была бы ошибочно исключена условием `rank <= 3`.

## Зачем нужен PARTITION BY

```sql
PARTITION BY e.departmentId
```

Эта конструкция создаёт отдельный рейтинг для каждого отдела. Без неё все сотрудники компании участвовали бы в одном общем рейтинге, и запрос вернул бы три максимальные зарплаты по всей таблице.

Разделение выполняется по идентификатору отдела, а не по его названию. Это надёжно даже в случае, если разные отделы имеют одинаковые названия.

## Почему фильтрация вынесена наружу

Оконные функции вычисляются после `WHERE` на том же уровне запроса. Поэтому псевдоним `rank` нельзя использовать в фильтре рядом с выражением `DENSE_RANK`.

Подзапрос сначала присваивает ранги всем сотрудникам, после чего внешний `WHERE` отбирает нужные позиции.

## Пограничные случаи

- Если в отделе меньше трёх уникальных зарплат, возвращаются все его сотрудники.
- Если несколько сотрудников имеют одну из трёх максимальных зарплат, возвращаются все они.
- Количество строк для отдела может быть больше трёх, потому что задача ограничивает количество уникальных зарплат, а не количество сотрудников.
- Итоговая сортировка условием задачи не требуется, поэтому внешний `ORDER BY` можно не добавлять.

## Что важно запомнить

- **Рейтинг строится отдельно для каждого отдела.** За это отвечает `PARTITION BY departmentId`.
- **Зарплаты сортируются по убыванию.** Самая высокая получает ранг `1`.
- **DENSE_RANK ранжирует уникальные значения без пропусков.** Это точно соответствует формулировке о трёх максимальных уникальных зарплатах.
- **Сотрудники с одинаковой зарплатой сохраняются.** Они получают одинаковый ранг и вместе проходят фильтр.
- **ROW_NUMBER ограничивает строки, а не уникальные зарплаты.** Для этой задачи он не подходит.
- **RANK может пропустить нужную позицию после ничьей.** Здесь нужен именно плотный ранг.
- **Оконный результат фильтруется на внешнем уровне.** Псевдоним `rank` ещё недоступен в `WHERE` того же запроса.
